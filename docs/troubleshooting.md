# トラブルシューティング

## 画面が開かない

1. `start_patch_app.bat` の黒い画面にエラーがないか確認します。
2. Edgeで `http://127.0.0.1:17345` を直接開きます。
3. ポート使用中の場合、ハンバーガーメニューのポートを変更して再起動します。
4. PWAだけを開いている場合は、先に `start_patch_app.bat` を実行します。

## VPN経由や別端末からアクセスできない

1. **待受ホストが `127.0.0.1` になっている場合**:
   - 画面右上の歯車（設定ドロワー）を開き、「待受ホスト」を `0.0.0.0` に変更して「設定を保存」した後に再起動します。
   - または、起動時に `--allow-vpn`（または `--host 0.0.0.0`）オプションを渡して起動します。
     - Windows: `start_patch_app.bat --allow-vpn`
     - macOS: `./start_patch_app.command --allow-vpn`
     - 直接実行: `python -m rep_patch --allow-vpn`
2. **Tailscale MagicDNS（`*.ts.net`）でアクセスしたい場合**:
   - `data/settings.local.json` の `listen_host` が `0.0.0.0` に設定されていることを確認します（または設定ドロワーから変更）。
   - 起動時のコンソールログに `TailscaleアクセスURL: http://<マシン名>.<tailnet>.ts.net:17345/` が出力されます。
   - ブラウザでそのURLを開くことで、Tailscaleネットワーク内の端末から直接アクセスできます。
3. **アクセス元IPがブロックされている場合**:
   - セキュリティ保護のため、パブリックIPからの接続は403エラーで遮断されます。VPN（Tailscale、社内VPN等）または同一プライベートLAN（RFC 1918）内のIPアドレスから接続しているか確認してください。
4. **OSのファイアウォールでポートが閉じている場合**:
   - サーバー側マシンのファイアウォール設定で、TCPポート `17345` への受信通信が許可されているか確認してください。


## pip installに失敗する

- Pythonが3.10以上か確認します。
- pipだけに許可されたインターネット経路が利用可能か確認します。
- `requirements.lock` を手動編集しないでください。
- ハッシュ不一致は配布ファイルの変更またはパッケージ取得経路の問題です。`--no-deps` や `--trusted-host` で回避しないでください。

## ZIPが一覧に出ない

- ファイル名が `myao_app_patch` で始まり、`.zip` で終わるか確認します。
- 既定フォルダは `%USERPROFILE%\Downloads` です。
- 別フォルダの場合はハンバーガーメニューから変更します。

## パスワードが異なる／改変エラー

自宅と会社で同じパスワードを設定してください。正しい場合はZIPを再ダウンロード・再移送します。マニフェストや分割ファイルを手動編集しないでください。

## パッチ連番が欠けている

古いパッケージが削除されたか、ZIPが最新でない可能性があります。GitHubの最新ブランチZIPを取得してください。パッチ専用リポジトリで公開済み連番を削除してはいけません。

## 未コミット内容が想定と異なる

Patch Appは自動コミットを停止します。次を確認してください。

- パッチ適用後にファイルを手動編集していないか
- アプリが管理対象ファイルを自動生成していないか
- Git管理対象の設定を会社側だけで変えていないか

内容を手動で直して強制コミットせず、自宅側ソースと運用方針を揃えてください。

## 一部アプリだけ失敗した

他のアプリは正常に処理されています。エラー内容を直し、「このアプリだけ再実行」を使用します。失敗したアプリはバックアップから適用前へ復元されます。

## Gitバージョン・互換性が不明

「会社環境診断」を実行してください。日本語パス、CRLFテキスト、バイナリファイル、ファイル配置・削除とGit同期を一時リポジトリで実際に検証します。診断に失敗したGitでは本番適用しないでください。
