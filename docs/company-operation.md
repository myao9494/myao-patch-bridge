# 会社側の導入・運用

## 動作条件

- 64bit Windows
- Python 3.10以上
- Git
- Microsoft Edge
- 初回導入・更新時のみpip通信が許可されていること

Git clone、Node.js、npm build、管理者権限は不要です（フロントエンドはビルド済み成果物が同梱されています）。

## 初回導入

1. `myao-patch-bridge` のGitHub ZIPを会社へ持ち込み、固定フォルダへ展開します。
2. `install_company.bat` を実行します（`.venv` が作成できない環境では自動的にシステムPython環境へインストールされます）。
   - コマンドで手動インストールする場合: `python -m pip install --require-hashes -r requirements.lock`
3. `start_patch_app.bat` をダブルクリックして実行します（またはコマンドプロンプトで `set PYTHONPATH=src && python -m rep_patch`）。
4. Edgeで `http://127.0.0.1:17345` が開きます。
5. Edgeのインストールアイコン、または画面の「アプリとしてインストール」を押します。

`install_company.bat` は `.venv` が利用可能な場合は `.venv` を作成し、`requirements.lock` のバージョンとSHA-256に一致するPythonパッケージだけをpipで安全に取得します。

PWAをインストールしてもPythonサーバーは必要です。利用前に必ず `start_patch_app.bat` を起動してください。


## 初期設定

ハンバーガーメニューで「会社」を選択し、次を設定します。

- `000_work` 配下のアプリルート
- Obsidian設定リポジトリ
- ZIP検索フォルダ（既定は `%USERPROFILE%\Downloads`）
- 自宅と同じパッチ検証パスワード

アプリ名は自宅と会社で同じフォルダ名を使用します。異なるアプリだけは `company_repo_paths` で個別対応できます。

最初に「会社環境診断」を実行し、全項目が成功することを確認してください。診断は一時リポジトリだけを使用し、本物のアプリを変更しません。

## 通常の週次運用

### 1. ZIPを置く

自宅でGitHubの `myao_app_patch` をZIPダウンロードし、会社の `%USERPROFILE%\Downloads` へ置きます。展開は不要です。

### 2. ZIPを検証する

1. Patch Appを起動します。
2. Downloads一覧から最新ZIPを選びます。
3. 「署名と内容を検証」を押します。
4. `VERIFIED` が表示されることを確認します。

パスワード不一致、改変、分割欠落、SHA-256不一致、安全でないZIPパスがある場合は適用できません。

### 3. 全アプリへ適用する

前回パッチを1週間運用して問題がなければ、「前回分をコミットして全適用」を押します。

アプリごとに次を実行します。

1. 前回の未コミット内容が想定どおりか検証
2. `git add -A`
3. `[myao-patch] アプリ名 patch-連番` で自動コミット
4. クリーン状態を確認
5. 新しいパッチを事前検査
6. バックアップ作成（新規追加・削除・変更予定の全パス）
7. 未適用連番を順番に適用
   - パッチ内に同梱された差分ファイル実体（`added_files/` 内の変更・新規ファイル）の直接上書き配置（階層ディレクトリ自動作成）
   - 削除対象ファイルの確実な消去（ワーキングツリーからの削除）
8. `git add -A` でステージングし、適用後blobを検証
9. `git reset` で未ステージ・未コミット状態に戻す（変更・新規ファイルは実体として残り、削除ファイルは消去された状態が維持されます）

新しい変更はコミットせず、そのまま実運用で確認します。


## リポジトリ個別操作

全アプリの一括適用・コミットに加え、画面下部の「会社側リポジトリ個別操作」エリアからリポジトリ単位で操作できます。

- **リポジトリ状態の確認**:
  - 各リポジトリカードで、未コミット変更の有無・件数や保留中のパッチ連番、ブランチ、HEADコミットを確認できます。
- **個別コミット（「このアプリをコミット」）**:
  - 対象リポジトリだけを安全にコミットします。保留中パッチがある場合は `[myao-patch] アプリ名 patch-連番` でコミットされ、手動変更の場合は `[myao-patch] アプリ名 update` としてコミットされます。
- **個別適用（「このアプリに適用」）**:
  - ZIP検証後、特定のリポジトリだけにパッチを適用します。

## 一部アプリが失敗した場合

- 失敗したアプリは適用前の状態へ復元されます。
- 他のアプリはそのまま続行します。
- 結果欄に失敗理由が表示されます。
- 原因を解消後、カードの「このアプリに適用」または「このアプリだけ再実行」を押します。

## 修正パッチを重ねる場合

前回パッチの動作確認で問題が見つかった場合は、前回分を破棄・コミットせず、自宅から修正パッチを受け取ります。

新しいZIPを検証後、「修正パッチを重ねる」を押します。現在の未コミット内容が前回の想定結果と一致する場合だけ、次の修正パッチが追加適用されます。

## Patch Appの更新

1. Patch Appを終了します。
2. 新しい `myao-patch-bridge` ZIPを会社へ持ち込みます。
3. 既存フォルダへ上書きします。
4. `install_company.bat` を再実行します。
5. `start_patch_app.bat` を起動します。

`data/settings.local.json`、対象リポジトリの `.git/rep-patch/state.json`、バックアップはZIPに含まれないため維持されます。
