# セキュリティ設計

## ネットワーク境界

- 実行時の待受は `127.0.0.1` のみ
- `0.0.0.0` やLANインターフェースでは待ち受けない
- 既定ポートはPWAオリジンを固定するため `17345`
- Patch App実行時に外部HTTP通信を行うコードはない
- 外部通信は利用者が明示的に実行するpipインストールと、自宅モードの `git push` だけ
- 会社モードでは公開APIからパッチ公開処理を拒否

## ブラウザ境界

- 変更APIには起動ごとのランダムなセッショントークンが必要
- API応答は `Cache-Control: no-store`
- Service WorkerはAPIをキャッシュしない
- `X-Frame-Options: DENY`
- `Content-Security-Policy` で同一オリジンだけを許可
- 外部フォント、CDN、分析、テレメトリーを使用しない

## パッケージ正当性

パスワードからPBKDF2-HMAC-SHA-256で鍵を導出し、以下へHMAC-SHA-256署名を付けます。

- `package-index.json`
- 各 `manifest.json`

各分割パーツと復元後パッチにはSHA-256を記録します。パスワードはパッチ専用リポジトリへ保存しません。

パスワードは `data/settings.local.json` に平文保存されます。個人利用という前提の簡易的な改変検知であり、強固な秘密鍵管理の代替ではありません。

## ZIP検査

- ZIPを一括展開しない
- 絶対パス、ドライブ文字、`..` を拒否
- 重複パスを拒否
- ファイル数上限: 20,000
- 展開後合計上限: 8 GiB
- JSON上限: 20 MiB
- 分割ファイル上限: 1パーツ50 MiB
- マニフェストに記載されたファイルだけを読み込む

## ファイル書き込み境界

- 登録済みGitリポジトリ配下だけを書き換える
- リポジトリ外を指すパスとシンボリックリンクを拒否
- パッチに含まれるスクリプトや実行ファイルをPatch App自身は実行しない
- 適用前に対象ファイルを `.git/rep-patch/backups` へ保存
- アプリ単位で失敗時復元
- 通常操作で無条件の変更破棄を行わない

## Git検証

会社と自宅のコミットIDは比較しません。`git apply --index` によるpreimage blob検証と、適用後の全tracked blob一覧の一致を使用します。

会社側で想定外の変更、追加ファイル、削除、競合がある場合はコミット・適用を停止します。`.gitignore` 対象の実行時ファイルはGit検証の対象外です。

## 依存関係

- Python依存は `requirements.lock` で完全固定
- `pip --require-hashes` で配布物のSHA-256を検証
- React依存は `package-lock.json` で固定
- 会社ではReactビルド済み成果物を使用し、npmを実行しない
